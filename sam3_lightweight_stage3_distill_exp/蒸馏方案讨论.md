# Stage-3 蒸馏方案讨论

## 1. 目标和起点

教师候选：`../sam3_detr_exp/weights_lora/roadline_r8_a16_lr2e4.best.pt`

学生起点：`../sam3_lightweight_stage3_exp/weights_lora/roadline_stage3_ev_m.best.pt`

统一真值评测结果：

| 模型 | 白实线 IoU | 白虚线 IoU | 白实线召回率 | 白虚线召回率 |
|---|---:|---:|---:|---:|
| Base DETR 最佳 LoRA | 0.724 | 0.681 | 0.788 | 0.823 |
| Stage-3 最佳 LoRA | 0.391 | 0.215 | 0.514 | 0.240 |

首要目标是提高白虚线召回率，同时控制斑马线等阴性类别误检。最终导出模型仍只保留 Stage-3，教师和训练期适配器不进入部署模型。

## 2. 教师和学生

教师使用 Base DETR 最佳 LoRA，全程冻结并保持 `eval()`。学生从现有 Stage-3 最佳 LoRA 继续。

这里必须区分两个概念：

- **蒸馏什么能力**：蒸馏教师整个 DETR 的分类、定位、Query 表征和掩码能力。
- **用哪些学生参数吸收知识**：可以只训练 LoRA，也可以训练完整学生 DETR。

蒸馏信号来自整个教师 DETR，并不等于只蒸馏教师 LoRA。教师 LoRA 只是教师完成道路标线微调后的权重组成部分。

当前已确认先实施 **P0 LoRA 蒸馏**：冻结学生图像编码器、MobileCLIP-S0 和 DETR 基础权重，只训练现有 Transformer LoRA、点积分类头和分割头。这样先以最低训练成本验证蒸馏信号和匹配逻辑是否有效。

逐层蒸馏作为 P1 紧跟 P0 实施。完整 Decoder 和完整 DETR 蒸馏分别顺延为 P2、P3，作为后备方案。

必须设置一个“无蒸馏、但继续训练相同轮数”的学生对照组，排除收益只是来自额外训练轮数。

### 蒸馏方案档位

| 档位 | 可训练部分 | 用途 |
|---|---|---|
| P0：LoRA 最终层蒸馏 | 现有 Transformer LoRA、点积分类头、分割头 | 先实现最终层输出蒸馏 |
| P1：LoRA 逐层蒸馏 | 与 P0 相同 | 在 P0 上增加最后 2～3 层分类和框蒸馏 |
| P2：完整 Decoder 蒸馏 | Decoder、点积分类头、分割头 | P0/P1 不足时的后备方案 |
| P3：完整 DETR 蒸馏 | Transformer encoder、decoder、点积分类头、分割头 | 最后考虑的容量上限 |

当前固定先实现 P0，再实现 P1。P2/P3 暂不实施。

以后若进入 P2/P3，需要先把现有 LoRA 增量合并进基础线性层，再移除参数化结构并解冻对应模块。不能一边保留可训练 LoRA 参数化、一边无意中重复训练同一基础权重。

## 3. Query 对齐原则

教师和学生的 Query 顺序没有稳定对应关系，不能直接让第 `i` 个教师 Query 拟合第 `i` 个学生 Query。

建议第一版这样匹配：

1. 教师使用未经过推理阈值截断的原始输出与真实实例匹配，避免先阈值过滤造成召回损失。
2. 按分类、框和 mask 组合代价做教师到真值的 O2O 匹配，再依据教师置信度和教师对真值的 IoU 做质量门控。
3. 学生预测用现有 Hungarian matcher 与真实实例匹配。
4. 只有指向同一个真实实例的教师和学生预测才计算实例级蒸馏。
5. 未匹配真实标注的教师预测第一版不作伪标签，防止教师误检传播。

建议加入“选择性蒸馏”：教师对应实例质量太低时只保留真实标签监督，不计算该实例的软蒸馏；可进一步只在教师比学生更接近真值时加强蒸馏。这样能避免学生模仿教师的局部错误。质量门控阈值应根据训练集教师预测分布确定，不能直接复用推理阈值 0.5。

## 4. 蒸馏信号

### 分类与存在性必须分开

SAM3 推理的最终分数不是单独的 `pred_logits`，而是：

```text
sigmoid(pred_logits) × sigmoid(presence_logit_dec)
```

因此需要两项损失：

- `L_query_cls`：匹配 Query 的连续分类 logits，使用 Bernoulli KL 或 soft BCE
- `L_presence`：每条文本提示是否在图中出现的 `presence_logit_dec`

存在性蒸馏对当前问题尤其重要：Stage-3 在无斑马线的 10 张图片中仍输出 12 个斑马线实例，而教师为 0。对正提示和负提示应分开做 batch 均衡，不能让大量背景 Query 淹没正实例。温度先用 `T=2`，但必须同时记录教师与学生概率直方图，检查教师是否需要校准。

### 边界框

对匹配实例计算归一化框的 L1 和 GIoU。道路标线细长，框只能辅助定位，权重不宜过高。

### 掩码

这是第一版最重要的蒸馏项：

- 使用教师连续 mask logits，不先二值化
- 在学生原生低分辨率 mask 尺度计算，避免先放大到 1008 造成显存浪费
- resize 教师 logits 到学生原生尺寸
- 采用 soft BCE 与 soft Dice
- 只蒸馏指向同一真实实例的掩码
- 用教师实例置信度给每个实例加权，低置信教师预测影响更小
- 对真实标注附近和教师不确定边界适度加权，降低大面积易分类背景的占比

### Decoder Query 特征

教师和学生隐藏维度若不同，需要训练期线性投影。只对已匹配 Query 计算余弦距离或归一化均方误差。该投影只用于训练，导出时删除。建议第二阶段再加入。

### 图像特征

Base 与 EfficientViT 的层级、空间尺寸和通道差异很大，需要多尺度空间对齐和通道投影，成本最高。第一版不做；只有输出级蒸馏收益不足时再讨论。

## 5. 推荐分阶段路线

### 对现有 DETR LoRA 监督损失的评价

现有 `loss-mode=sam3` 应继续作为 P0 的监督底座，不建议改回简化 loss。它包含：

- O2O Hungarian 匹配
- box L1，权重 5
- GIoU，权重 2
- IABCE 分类，权重 20，正样本分数同时参考预测概率与框 IoU
- prompt presence，权重 20
- mask focal，权重 200
- mask Dice，权重 10
- Decoder aux 分类/框监督
- O2M 一对多监督，总体系数 2

优点是完整覆盖存在性、实例分类、定位和掩码，O2M 对细碎白虚线的召回尤其有价值。Base 的统一评测结果也证明这套监督目标能学到很强的道路标线能力。

需要注意：

1. 对没有真值的负提示，IABCE 会关闭逐 Query 分类损失，主要依赖 presence 抑制整条提示。因此蒸馏必须强化负提示的 `L_presence`，同时监控每类负提示误检。
2. 数值为 200 的 mask 权重不等于 mask 梯度一定大，因为原始 focal loss 已按像素和实例归一化。不能只根据权重或总 loss 判断主导项，必须测梯度范数。
3. 总 loss 同时累加主输出、多个 aux 输出和两倍 O2M，`loss=4` 或 `loss=8` 本身没有跨模型可比性。
4. 现有训练按最低 val loss 保存最佳权重，可能与最终 IoU、实例召回不一致；蒸馏实验必须改为任务指标选模。
5. 第一版监督侧保留 aux 与 O2M，但蒸馏侧只作用于最终 O2O 输出，避免重复放大 O2M 和 aux 的贡献。

### P0：LoRA 最终层输出蒸馏

保留真实标签监督，增加分类、框和掩码蒸馏：

现有原生 SAM3 监督损失内部权重为：分类和 presence 各 `20`，mask focal 为 `200`，mask Dice 为 `10`。因此不能把未经归一化的蒸馏损失以 `1.0` 或 `2.0` 直接相加，否则很可能被监督损失淹没。

第一版改为先把各蒸馏分量按有效匹配数和像素数归一化，再组合成 `L_KD`：

```text
L_KD = 1.0 × L_query_cls
     + 1.0 × L_presence
     + 1.0 × L_box_l1
     + 1.0 × L_box_giou
     + 2.0 × L_mask_soft_bce
     + 1.0 × L_mask_soft_dice

总损失 = L_supervised + λ_kd × L_KD
```

`λ_kd` 不固定拍成一个大数：前 5% 训练步从 0 线性升到 1；运行 50～100 step 后比较 `L_supervised`、`L_KD` 以及二者对 LoRA 参数的梯度范数。如果蒸馏梯度小于监督梯度的约 20%，提高 `λ_kd`；如果超过约 100% 且监督指标恶化，降低它。建议搜索 `λ_kd={0.5, 1.0, 2.0}`，不要同时搜索每一个子损失权重。

第一版只蒸馏最终 Decoder 输出，不蒸馏所有 aux/O2M 输出。现有监督损失已经覆盖 aux 和 O2M；一开始对所有层蒸馏会显著放大损失且难以定位问题。

P0 内部先验证 `r=8`，不同时提高 LoRA 秩，避免实验变量过多。

P0 的蒸馏范围固定为：

- 最终层 Query 分类 logits
- 最终层 presence logit
- 最终层 box L1 与 GIoU
- 最终层低分辨率 mask logits
- 不蒸馏 aux 输出
- 不蒸馏 O2M 输出
- 不蒸馏中间 Query 特征

先完成 P0 的冒烟、短训和完整训练。只有它相对无蒸馏基线取得稳定收益，才进入 P1。

### LoRA 秩升级路线

当前学生 LoRA 为 `r=8, alpha=16`。如果 r8 蒸馏确认训练稳定但容量不足，再依次尝试：

| 实验 | rank | alpha | 说明 |
|---|---:|---:|---|
| P0-R8 | 8 | 16 | 第一版与现有学生完全一致 |
| P0-R16 | 16 | 32 | 保持 `alpha/rank=2` |
| P0-R32 | 32 | 64 | 仅在 R16 仍有明确欠拟合时尝试 |

不能把 r8 checkpoint 直接加载到 r16 或 r32 参数中。正确迁移步骤是：

1. 加载 Stage-3 基础模型与当前最佳 r8 LoRA。
2. 将 r8 增量合并到对应基础权重。
3. 移除旧 LoRA 参数化。
4. 在合并后的权重上挂载新初始化的 r16 或 r32 LoRA。
5. 点积分类头和分割头继续继承现有训练权重。

这样既保留当前 r8 已学到的道路标线能力，也给后续蒸馏提供更大的低秩容量。

### P1：LoRA 逐层输出蒸馏

P1 在 P0 基础上增加 Decoder 中间层的分类和框蒸馏，不改变学生可训练参数范围：仍然只训练 r8 LoRA、点积分类头和分割头。

教师与学生分别在最终层和 GT 做 Hungarian matching，通过相同 GT 建立教师—学生 Query 对。得到最终层 Query 索引后，将各自的 Query 槽位沿用到中间层，避免每层独立匹配导致实例身份跳变。

如果教师和学生 Decoder 层数不同，按归一化深度映射：

```text
教师层索引 = round(学生层相对深度 × 教师总层数)
```

第一版逐层蒸馏只使用最后 2～3 个 Decoder 层，并让越靠近最终层的权重越大。例如三层权重为 `0.25、0.5、1.0`。

```text
L_total = L_supervised
        + λ_final × L_final_kd
        + λ_layer × Σ w_l × (
              L_query_cls_l
            + L_box_l1_l
            + L_box_giou_l
          )
```

初始设置：`λ_final=1.0`，`λ_layer=0.25`。P1 第一版不做中间 mask、不做 O2M 蒸馏，也不直接拟合 Query 隐特征。

只有逐层分类/框蒸馏有效后，才单独讨论 Query 特征或 box delta 轨迹蒸馏。

### P1 之后的二选一消融

- 教师高置信伪标签
- 多尺度图像特征蒸馏

二者不应第一次就同时加入，否则无法判断收益来源。

## 6. 在线还是离线

在线蒸馏能直接获得连续 logits、Query 和特征，数据增强也容易同步，但 Base 教师约 8.4 亿参数，会明显增加显存和训练时间。

离线缓存训练更轻，适合反复消融，但随机几何增强难以对齐；保存全分辨率 mask 和 Query 也会占用大量磁盘。

当前建议：先用少量样本做在线冒烟测试，确认匹配和损失正确；完整训练改用离线缓存。离线缓存不保存全部 200 个 Query，只保存每个真实实例匹配到的教师 logits、框、低分辨率 mask logits，以及每条提示的 presence logit。这样缓存更小，也避免把大量教师背景 Query 固化下来。

离线缓存时必须限制几何增强：

- 颜色、亮度等不改变坐标的增强可以继续使用
- 翻转、缩放、裁剪必须对缓存框和 mask 做完全相同的变换
- 若现有数据管线无法保证同步，第一版关闭随机几何增强

否则教师软目标会与学生输入错位，mask 蒸馏会产生反向效果。

## 7. 优化器与训练日程

从已经收敛的 Stage-3 最佳 LoRA 继续训练，不建议沿用首次微调的 `2e-4` 全程恒定学习率。P0-R8 第一版建议：

- LoRA 学习率：`5e-5`
- 点积分类头与分割头：`2e-5`；若实现分组优化器则单独设置
- AdamW，weight decay 保持 `1e-2`
- 前 5% step 线性 warmup，之后 cosine decay
- 梯度裁剪 `max_norm=1.0`
- 先训练 10 轮，并使用指标早停，避免已有能力被教师噪声覆盖

可选地维护学生权重 EMA（如 `0.999`），验证时同时比较原权重与 EMA；只有稳定提升才保留，第一版不把它设为必要条件。

## 8. 第一组消融实验

| 实验 | 参数范围 | 最终层蒸馏 | 逐层分类/框 | 用途 |
|---|---|---|---|---|
| Control-R8 | r8 LoRA＋输出头 | 否 | 否 | 相同轮数的无蒸馏基线 |
| P0-R8 | r8 LoRA＋输出头 | 是 | 否 | 最终层输出蒸馏 |
| P1-R8 | r8 LoRA＋输出头 | 是 | 是 | 在 P0 上增加逐层蒸馏 |
| P0-R16 | r16 LoRA＋输出头 | 是 | 否 | r8 容量不足后的升秩实验 |
| P1-R16 | r16 LoRA＋输出头 | 是 | 是 | 仅在 R8 逐层蒸馏仍不足时考虑 |

固定执行顺序：

1. `Control-R8`
2. `P0-R8`
3. 确认 P0 有效后运行 `P1-R8`
4. r8 有收益但容量不足时，优先做 `P0-R16`
5. R16 是否加入逐层蒸馏由前四组结果决定

P2/P3 暂缓。

## 9. 验证与保存原则

- 主比较固定报告阈值 0.5，同时报告 0.3、0.4
- 记录白实线和白虚线的 IoU、精确率、召回率
- 单独记录各阴性类别误检，重点关注斑马线
- union micro IoU 继续保留，但它不会惩罚重复实例，不能单独决定最佳权重
- 增加实例级 mask AP50、AP75、平均召回率，或至少增加 Hungarian 匹配后的实例 precision/recall/F1
- 最佳权重以两类实例指标和 union IoU 的组合为主，并约束阴性误检，而不是只看总 loss
- 每种新增蒸馏项必须单独消融
- 不覆盖原 Stage-3 权重

## 10. 需要我们确认的决策

1. 完整训练采用在线还是离线缓存？当前建议：在线冒烟、离线完整训练。
2. 学生是否从现有最佳 LoRA 继续？当前建议：是，同时保留原始 Stage-3 起步的对照实验。
3. 第一版是否只做输出级蒸馏？当前建议：是。
4. 是否使用教师伪标签？当前建议：第一版不用。
5. 学生训练哪些参数？已确认先做 P0，再做 P1；完整 Decoder P2 和完整 DETR P3 暂缓。
6. LoRA 秩如何安排？已确认先用现有 r8，效果不足时依次尝试 r16、r32，并保持 `alpha/rank=2`。
7. 最佳权重按什么保存？建议新增实例级指标，以实例 F1/AP、union IoU 和阴性误检共同决定。
8. 蒸馏阶段如何安排？已确认 P0 实现最终层蒸馏，P1 在 P0 上增加最后 2～3 层的分类与框蒸馏，后续编号顺延为 P2/P3。

## 11. 实现前必须通过的正确性检查

1. 同一图片和提示下，教师缓存结果与在线教师结果数值一致。
2. 教师、学生和真值的框坐标均确认是同一种 `cxcywh` 归一化格式。
3. 教师 mask logits resize 后与真值在空间上重合，随机抽样可视化检查。
4. 匹配关系中每个真实实例最多对应一个 O2O 教师 Query 和一个学生 Query；当真实实例数超过教师 Query 数时，未匹配实例只使用真实标签监督，不计算蒸馏损失。
5. 负提示没有真实框时，仍能计算 presence 与背景分类蒸馏，且不会访问空 mask。
6. `L_KD=0` 时训练结果应与现有 Stage-3 继续训练基线一致。
7. 分别反向传播监督损失和蒸馏损失，确认 LoRA、分类头、分割头都能获得有限且非零梯度。

P0 已按上述方案实现，当前代码包含教师缓存生成、最终层蒸馏训练、分项 loss 日志、梯度范数日志和单步冒烟验证。P1 逐层蒸馏尚未实现，需等待 P0 完整训练结果。
