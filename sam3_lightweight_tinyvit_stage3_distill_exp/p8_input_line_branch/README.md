# P8 输入侧504分辨率细线分支

## 动机与起点

P8从P7实际IoU最佳权重`weights/p7_highres_fpn_frozen_p6.epoch9.pt`开始。P7最终平均IoU为0.6003，但`gate_high=-0.0171`，说明把已经经过TinyViT编码的Stage 1方向特征简单插值到`288×288`几乎没有价值。极细标线可能在Stage 1之前就已经显著衰减，因此P8改为在输入侧先提取细线，再进行空间压缩。

P8冻结P7和此前全部参数，只训练新增输入细线分支，零门控初始化确保初始输出严格等价于P7 epoch 9。

## 结构

```text
RGB：3×1008×1008
↓ PixelUnshuffle(2)，仅重排像素、不做平均
12×504×504
↓ 3×3卷积stem
16×504×504
├── 横向DSConv，16通道，核长9
└── 纵向DSConv，16通道，核长9
↓ 拼接
32×504×504
↓ 双线性抗混叠缩放到288 + Depthwise 3×3 + Pointwise 1×1
256×288×288
↓ 乘以由FPN[1] 144层生成的语义门控
↓ 零初始化残差门控
加到P7 FPN[0]
```

PixelUnshuffle把每个`2×2`像素搬到四组通道，避免使用stride-2卷积时直接丢失极细标线像素。504层DSConv负责在进一步下采样之前聚合细线连续性；Stage 2语义门控负责抑制裂缝、阴影、路缘和车辆边缘等非标线细长结构。

## 普通长条卷积接口

训练入口支持：

```text
--operator dsconv
--operator strip_conv
```

`strip_conv`使用普通`1×9`横向卷积和`9×1`纵向卷积。第一组正式实验只运行DSConv；如果P8-DSConv有效，再使用相同起点、通道、融合位置和轮数运行普通长条卷积。只有DSConv明显优于该对照，才能把增益归因于动态蛇形偏移。

## 训练

默认四卡、每卡batch 4（全局batch 16）、5轮：

```bash
bash sam3_lightweight_tinyvit_stage3_distill_exp/p8_input_line_branch/scripts/train_p8_input_dsconv.sh
```

输出：

- 日志：`logs/p8_input_dsconv_frozen_p7/`
- 最佳验证损失权重：`weights/p8_input_dsconv_frozen_p7.best.pt`
- 逐轮权重：`weights/p8_input_dsconv_frozen_p7.epochN.pt`

训练仍保留真实标签监督、最终输出蒸馏和三尺度图像特征蒸馏。最初保守配置为每卡batch 1，正式启动后实测每卡仅使用约10～12 GiB/80 GiB，GPU利用率约53%～74%，因此默认提高到每卡4。预计显存仍有充足余量；暂不直接设为8，避免动态采样、验证阶段或个别大实例batch产生峰值溢出。

## 验收标准

P7基线为实线IoU 0.6319、虚线IoU 0.5687、平均IoU 0.6003。P8进入后续实验的最低条件：

- 两类平均IoU至少达到0.610；
- 白虚线IoU不能下降；
- 斑马线误检不能明显超过11，护栏保持0；
- 504分辨率分支的延迟和显存必须单独记录。

如果5轮仍不能超过0.610，停止输入DSConv路线，不增加通道或训练轮数。如果有效，再执行普通长条卷积严格对照。

## 正式训练结果

正式训练是在脚本默认batch调整前启动的，因此实际使用四卡、每卡batch 1，而不是文档现默认的每卡batch 4。计划的5轮已全部完成，并逐轮使用相同10图、7提示、阈值0.5评测：

| epoch | val/loss | val/supervised | 实线IoU/Recall | 虚线IoU/Recall | 平均IoU |
|---:|---:|---:|---:|---:|---:|
| 0 | 9.1876 | 5.3093 | 0.6511 / 0.7758 | 0.5800 / 0.6737 | 0.6155 |
| 1 | 9.1516 | 5.2712 | 0.6665 / 0.7847 | 0.5884 / 0.6818 | 0.6274 |
| 2 | 9.1394 | 5.2585 | 0.6741 / 0.7892 | 0.5938 / 0.6866 | 0.6340 |
| 3 | 9.1349 | 5.2535 | 0.6760 / 0.7906 | 0.5957 / 0.6890 | 0.6358 |
| **4** | **9.1322** | **5.2508** | **0.6772 / 0.7900** | **0.5960 / 0.6883** | **0.6366** |

任务指标最佳为epoch 4。与P7正式最佳对比如下：

| 指标 | P7 epoch 9 | P8 epoch 4 | 变化 |
|---|---:|---:|---:|
| 白实线IoU | 0.6319 | 0.6772 | +0.0453 |
| 白实线Recall | 0.7603 | 0.7900 | +0.0297 |
| 白虚线IoU | 0.5687 | 0.5960 | +0.0273 |
| 白虚线Recall | 0.6604 | 0.6883 | +0.0279 |
| 两类平均IoU | 0.6003 | 0.6366 | +0.0363 |

5轮内验证loss持续下降，实线、虚线及平均IoU也逐轮提高；epoch 4相对epoch 0的平均IoU再提高0.0210，因此正式权重选择`weights/p8_input_dsconv_frozen_p7.epoch4.pt`。各轮斑马线误检均为11、护栏误检均为0，新增分支没有改善这项固定误检。

结果证明在TinyViT显著下采样之前提取原图侧细线特征有效，但P8平均IoU 0.6366相对Base + DETR LoRA的0.7021仍差0.0655。当前也不能把收益单独归因于动态蛇形偏移，仍需运行已经预留的普通长条卷积严格对照。

## 已完成验证

- 实际输入链路为`3×1008×1008 → 12×504×504 → 16×504×504`；横纵DSConv各输出`16×504×504`，最终残差为`256×288×288`。
- 总参数106,070,613，新增且可训练参数83,827；P7及以前全部参数保持冻结。
- 残差门控为0时，P8与P7 epoch 9的四级FPN输出逐元素一致，所有层最大绝对误差为0。
- 两batch冒烟首步只有残差门控有梯度；第二步stem、横纵方向算子、空间细化和语义门控均有非零梯度。
- 冒烟checkpoint包含20个P8张量，统一评测器能够自动挂载P5～P8并完成7提示词推理。
- 单图推理峰值显存约3814.8 MiB；该数值不代表正式训练峰值，正式脚本会在结束时额外打印训练峰值显存。
