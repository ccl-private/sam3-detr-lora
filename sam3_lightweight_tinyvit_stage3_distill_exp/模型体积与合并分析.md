# 轻量模型体积、权重合并与最终推理包分析

本文记录本地实际 `.pt` 文件的张量组成，区分基模、LoRA 增量、完整训练头、额外细线分支和
训练缓存，并给出每个实验最终推理模型大小的计算方法。统计单位均为 MiB（`1 MiB=2^20` 字节）。

## 1. 统计口径

目录占用、当前加载文件之和和最终推理模型大小不是同一个概念：

- 目录占用包含教师缓存、逐轮 checkpoint、测试输出和重复实验，不代表部署体积。
- 当前 Stage-3 推理使用“官方基模 + 实验 checkpoint”两个文件；两个文件包含重复权重，不能直接
  相加作为最终模型大小。
- 合并推理包会把 LoRA 增量折叠到原权重，用训练后的分类头和分割头覆盖基模同名模块，并只保留
  一份 P5～P8 额外分支。
- 下表的 FP32/FP16 是模型张量的理论体积；PyTorch 序列化元数据会带来少量额外开销，最终导出
  文件必须以实际文件字节数为准。

## 2. Stage-3 基模的实际内容

| 基模文件 | 当前文件大小 | `model` 图像模型张量 | 可从图像推理包删除的额外内容 |
|---|---:|---:|---:|
| EfficientViT Stage-3 | 446.70 | 371.76 | 约75 |
| TinyViT Stage-3 | 469.98 | 395.04 | 约75 |

额外约75 MiB主要来自 `preserved_base_model`。当前道路标线推理构建模型时使用
`enable_inst_interactivity=False`，加载器只读取 checkpoint 的 `model` 字典，因此该备份不参与
纯图像检测/分割推理，可以在正式部署导出时删除。

TinyViT Stage-3 的395.04 MiB FP32图像模型张量由以下部分组成：

| 模块 | FP32张量大小 |
|---|---:|
| TinyViT视觉编码器与neck | 107.82 |
| MobileCLIP-S0文本编码器 | 162.31 |
| DETR Transformer | 80.29 |
| 几何编码器 | 31.34 |
| 分割头 | 8.77 |
| 点积分类头 | 4.51 |

## 3. 当前所谓LoRA checkpoint为什么仍然很大

当前保存器按键名包含 `parametrizations` 进行筛选，因此不仅保存真正的 `lora_a/lora_b`，还保存
每个被参数化层的 `weight.original`。以P8 epoch 4为例：

| P8 checkpoint内容 | FP32张量大小 |
|---|---:|
| 重复保存的 `weight.original` | 115.875 |
| 真正的图像与DETR LoRA A/B | 4.406 |
| 完整点积分类头 | 4.513 |
| 完整分割头 | 8.770 |
| P5 Stage 2细线分支 | 3.418 |
| P6 Stage 1细线分支 | 1.150 |
| P7 FPN适配器 | 0.379 |
| P8输入细线分支 | 0.320 |
| 张量合计 | 138.831 |
| 实际文件大小 | 139.003 |

如果仍采用“基模 + 纯增量”两文件部署，P8真正需要单独保存的内容约为：

```text
LoRA A/B              4.406 MiB
两个完整训练头        13.282 MiB
P5～P8额外分支         5.267 MiB
--------------------------------
纯增量合计            22.955 MiB
```

因此当前约139 MiB的P8文件中，约115.875 MiB是可以消除的原始权重副本。

## 4. 哪些权重可以合并

### 4.1 可以精确合并

DETR LoRA和TinyViT图像LoRA都可以在推理前折叠：

```text
W_merged = W_original + (alpha / rank) * (lora_b @ lora_a)
```

推理态下LoRA dropout关闭，因此FP32合并前后应数值一致。合并后不再保存A/B，也不再依赖
PyTorch parametrization结构。点积分类头和分割头则直接覆盖基模同名权重。P4完整解冻的Stage 3
和neck也属于覆盖基模对应权重，剩余LoRA仍可继续合并。

### 4.2 不能折叠进原层，但可以放进同一个推理文件

P5～P8包含动态采样、非线性、门控和跨尺度融合，不能像LoRA一样代数折叠进TinyViT原权重：

- P5：Stage 2 DSConv细线分支；
- P6：Stage 1 DSConv细线分支；
- P7：高/中分辨率FPN适配器；
- P8：输入侧504分辨率DSConv分支。

它们可以作为正式模型结构的一部分统一写入一个推理 checkpoint。P8 checkpoint已经累计包含
P5、P6、P7和P8权重，部署P8时不需要再分别加载四个历史checkpoint。

教师模型、教师输出缓存、P1图像特征缓存、训练loss和优化器状态均不参与学生推理，不应进入
最终推理包。

## 5. 各实验最终推理体积

下表按“保留运行时MobileCLIP文本编码器、删除tracker备份和训练元数据”计算。当前加载合计只用于
说明本地加载方式的冗余，合并后体积才是部署模型的正确口径。

| 实验 | 当前本地加载方式 | 当前文件合计 | 合并后FP32 | 合并后FP16 |
|---|---|---:|---:|---:|
| Base + DETR LoRA | 7个Base图像模块 + 76 MiB LoRA | 大于3245 | 约3245 | 约1623 |
| 早期TinyViT固定词表 | 110 MiB基模 + 95 MiB LoRA | 约205 | 约110 | 约110（基模已为FP16） |
| EfficientViT Stage-3 LoRA | 446.70 + 94.48 | 541.18 | 371.76 | 185.88 |
| EfficientViT P0蒸馏 | 446.70 + 94.48 | 541.18 | 371.76 | 185.88 |
| TinyViT P0/P1/P2/P3 | 469.98 + 132～138 | 约602～608 | 395.04 | 197.52 |
| TinyViT P4 | 469.98 + 约163 | 约633 | 395.04 | 197.52 |
| TinyViT P5 | 469.98 + 137.14 | 607.12 | 398.46 | 约199.23 |
| TinyViT P6 | 469.98 + 138.29 | 608.27 | 399.61 | 约199.81 |
| TinyViT P7 | 469.98 + 138.68 | 608.66 | 399.99 | 约200.00 |
| TinyViT P8 | 469.98 + 139.00 | 608.98 | 400.31 | 约200.16 |

计算原则如下：

```text
合并后模型 = 基模model张量
           - 被替换模块的旧权重
           + 相同形状的合并权重或训练后权重
           + 无法折叠的新增结构
```

LoRA合并和头部覆盖不增加完整模型大小；P5～P8分别增加3.418、1.150、0.379和0.320 MiB。

## 6. 固定文本提示后的P8目标体积

P8保留运行时MobileCLIP时，仍支持输入任意文本；若部署只允许固定道路标线词表，可以预提取文本
特征并移除162.31 MiB FP32的MobileCLIP-S0：

| P8部署形式 | 预计模型张量大小 |
|---|---:|
| 运行时任意文本，FP32 | 约400.31 MiB |
| 运行时任意文本，FP16 | 约200.16 MiB |
| 固定道路标线词表，FP32 | 约238 MiB |
| 固定道路标线词表，FP16 | 约119 MiB |

几何编码器约31.34 MiB FP32。即使业务不输入点和框，当前前向仍可能构造空几何提示；在没有修改
前向并完成一致性测试前，不能直接从部署包删除。
