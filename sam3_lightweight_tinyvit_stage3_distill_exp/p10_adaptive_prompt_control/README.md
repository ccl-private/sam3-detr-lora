# P10 验证闭环提示控制

## 两阶段定义

阶段1为P9：从作者官方TinyViT Stage-3开始，挂载P5～P8完整结构，使用全部7个道路标线提示训练20轮。阶段2为本目录P10：从P9 epoch 19最佳权重开始，恢复原始图片随机采样，只根据验证集逐类别表现控制下一轮正提示保留率。

P10不删除GT实例、不遮挡图片、不修改损失，也不重新生成教师缓存。类别在图片中存在但本轮未被选择时，整个正提示不参与DETR监督和输出KD；它不会被错误地当作负提示。类别不存在时的内部负提示始终保留，域外纯负提示继续关闭。

## 验证指标

验证阶段复用已有前向输出，不额外运行模型。置信度阈值和mask阈值均固定为0.5；每个提示的预测实例mask取并集，GT实例mask也取并集，在完整验证集上累积micro IoU、Precision和Recall：

```text
val/iou/<类别>
val/precision/<类别>
val/recall/<类别>
```

训练集指标只记录，不进入控制器。验证集中正样本图片少于20张的类别不参与动态调整，正提示率固定为1.0。

## 控制器

P10 epoch 0仍使用全部提示，从epoch 0验证结束开始更新下一轮频率。需要注意，Lightning会先完成
epoch 0训练再执行验证，因此epoch 0指标不是未经训练的纯P9基线，而是P9权重完成一轮全提示续训
后的结果。每类验证质量定义为：

```text
quality = 0.7 × IoU + 0.3 × Recall
```

指标先执行EMA平滑，新一轮权重为0.3；以所有有效类别质量的中位数为参考。低于中位数的类别提高提示需求，高于中位数的类别降低提示需求。白虚线基础提示率同时受训练集实例先验约束：

```text
white_dashed_base_rate
= 目标虚实实例比 × 白实线实例数 / 白虚线实例数
= 2.0 × 40017 / 150242
= 0.5327
```

其他类别基础提示率为1.0。目标率限制在0.4～1.0；实际率采用0.2步长平滑更新，单轮最多变化0.1；质量差异小于0.02时进入死区，不因小波动调整。每个epoch通过图片路径、类别、epoch和随机种子确定性选择正提示，因此四卡结果一致且不同epoch会轮换图片。

## 选模

不再用验证总loss单独选模。有效类别的任务分数为：

```text
control_score
= 0.5 × macro IoU
+ 0.3 × macro Recall
+ 0.2 × 最弱类别质量
```

最佳权重按val/control_score最大保存，早停也监控该指标。固定10图测试集不参与频率控制或早停，只在训练结束后做最终比较。

## 四卡训练

```bash
bash sam3_lightweight_tinyvit_stage3_distill_exp/p10_adaptive_prompt_control/scripts/train_p10_adaptive.sh
```

最佳权重为../weights/p10_adaptive_prompt_control.best.pt；逐轮权重为../weights/p10_adaptive_prompt_control.epochN.pt。checkpoint元数据保存每轮IoU、Recall、使用提示率、目标提示率和下一轮提示率，便于完整回溯控制过程。

## 正式训练结果

四卡训练已完整完成10轮（epoch 0～9）。验证集`control_score`最佳点为epoch 4，最终epoch 9
没有超过它：

| 指标 | epoch 0 | epoch 4（验证最佳） | epoch 9（最终） |
|---|---:|---:|---:|
| `val/loss` | 8.5980 | 8.5076 | 8.5136 |
| `val/supervised` | 4.8769 | 4.8032 | 4.8047 |
| `val/macro_iou` | 0.7054 | 0.7102 | 0.7114 |
| `val/macro_recall` | 0.8287 | 0.8374 | 0.8330 |
| `val/control_score` | 0.7058 | **0.7143** | 0.7139 |

白虚线实际正提示保留率由1.0逐步降至epoch 9的0.5624，白虚线与白实线实际训练实例比由
3.75:1降到约2.17:1，接近预设2:1目标。白虚线在验证集没有因此崩溃，说明控制器实现和频率
约束按设计运行；但epoch 4以后综合指标进入平台，单纯继续减少强类提示没有给稀有类增加新的
图像形态。

## 固定10图结果

按验证集规则选择的epoch 4，以及训练最终epoch 9，均使用历史相同10张图和0.5阈值测试：

| 模型 | 白实线IoU/Recall | 白虚线IoU/Recall | 两类平均IoU |
|---|---:|---:|---:|
| P9 epoch 19 | 0.6284 / 0.6869 | 0.6595 / 0.7543 | **0.6439** |
| P9普通低学习率续训epoch 6 | 0.5865 / 0.6411 | 0.6647 / 0.7584 | 0.6256 |
| P10 epoch 4（验证最佳） | 0.5766 / 0.6242 | 0.6649 / 0.7601 | 0.6207 |
| P10 epoch 9（最终） | 0.5972 / 0.6502 | 0.6666 / 0.7607 | **0.6319** |

P10 epoch 9优于普通P9续训约0.0063，证明提示控制并非完全无效；但仍低于不续训的P9最佳
约0.0121。P10主要小幅改善白虚线，没有完全避免白实线在续训中退化，因此不能替代原始P9
作为旧10图口径下的最佳权重。

## 固定10图的代表性限制

历史固定10图并不是10个独立场景，而是同一无人机视频
`DJI_20251231162942_0002_V`的frame 001、005、009至037，相邻样本仅间隔4帧。10图共有白实线
268个实例、白虚线618个实例，实例数偏白虚线2.31倍；但真值像素分别为2,108,174和584,226，
面积又偏白实线3.61倍。这种“虚线实例多、实线单体面积大、场景高度重复”的构成不能代表道路
标线的跨场景和跨形态泛化。

因此这10图继续保留为历史“单视频航拍场景回归集”，用于和P0～P9保持数值可比；不能再单独
决定最终最佳模型，也不能把其两类平均IoU解释为总体道路标线能力。后续正式测试集应按视频片段
去重，每段最多抽1～2帧，并覆盖城市/乡村、直道/弯道、航拍/低视角、远近尺度和不同光照；同时
报告分类别micro IoU、逐图片macro IoU和Recall。

## 3张网络图跨形态检查

3张网络图片没有人工真值，只能比较候选数量并人工检查覆盖形态，不能计算IoU；可视化中的红色
仅表示没有真值可匹配，不代表人工确认的误检：

| 模型 | 白实线候选 | 白虚线候选 | 观察 |
|---|---:|---:|---|
| P8 epoch 4 | 10 | 41 | 覆盖最宽，但存在实线/虚线提示重叠响应 |
| P9 epoch 19最佳 | 8 | 26 | 城市图白实线消失，整体更保守 |
| P9 epoch 9中期 | 9 | 28 | 比P9最佳略多，仍未恢复城市图白实线 |
| P10 epoch 9 | **13** | **29** | 城市图白实线恢复，实虚线分离较P8克制 |

P10虽然没有超过P9的旧10图IoU，但在城市多车道、低分辨率斜视和乡村弯道3种域外形态上恢复
了P9消失的城市白实线，说明“旧10图略弱”和“跨形态覆盖改善”可以同时成立。由于网络图没有
真值，这一结果只能作为跨形态证据，不能反向把P10确定为总体最佳。

## 阶段结论

- 提示比例闭环实现有效，能够在不删除图片和GT的前提下把虚实实例训练比例拉近目标。
- P10优于普通低学习率续训，但没有超过原始P9；只靠减少强类提示不足以解决稀有类多样性。
- 当前验证集`control_score`、旧单视频10图和3张域外网络图给出的排序不一致，证明选模口径存在
  明显分布偏差。
- 下一阶段应从原始P9最佳权重重新出发，引入原图完整KD与增强图监督/输出KD的双路训练；不要
  从P10继续训练，也不要只依赖旧10图或验证总loss选模。
