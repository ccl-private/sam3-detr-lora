# P13-A：单教师无标签高置信输出蒸馏

本实验以现有P12为正式对照，但学生不加载P12权重，而是与P12一样从官方TinyViT Stage-3、
完整P8结构和相同随机种子重新训练20轮。唯一新增变量是无标签图片上的新Base教师输出KD。

教师固定为：

```text
sam3_detr_exp/negative_prompt_ablation/weights/roadline_r8_a16_lr2e4_no_generic_negatives.best.pt
```

官方SAM3 Base不参与伪标签筛选、融合或蒸馏。

## 已实现内容

- 从现有591图教师对比记录生成确定性候选清单，并预留100张域外评测候选。
- 仅缓存7个道路标线提示的Presence连续logit，以及组合置信度不低于0.5的top-50实例。
- 对高置信实例执行mask IoU 0.85的去重，避免近重复候选被反复蒸馏。
- 实例缓存保留软分类logit、归一化框和连续低分辨率mask logit。
- 教师实例和学生200个候选按软分类、框L1、GIoU和36×36软mask Dice代价做Hungarian集合匹配，
  不按Query编号对齐；匹配后再用原生低分辨率连续mask计算KD。
- 无标签损失包含Presence、软分类、框L1、GIoU、mask BCE和soft Dice。
- 教师无输出的提示只蒸馏Presence软值，不把200个候选构造为hard negative。
- 每个训练step使用等量有标签和无标签图片；有标签侧完整保留P12损失。
- 无标签总权重默认0.5，并在总训练步数前10%线性warmup。

P13-A明确不包含强弱增强、无标签全部候选排序、无标签跨提示关系、边界/中心线或Decoder逐层蒸馏。

## 执行顺序

1. 生成自动候选清单：

```bash
bash sam3_lightweight_tinyvit_stage3_distill_exp/p13_unlabeled_output_distill/scripts/prepare_unlabeled_manifests.sh
```

2. 默认直接使用`manifests/unlabeled_train_candidates.jsonl`开始P13-A。该清单已经过图片解码、去重和
   新教师组合置信度0.5正检出筛选，但仍可能含教师误检。若另做人工清理，可保存为
   `manifests/unlabeled_train_clean.jsonl`，并在后续命令前设置
   `UNLABELED_MANIFEST=.../unlabeled_train_clean.jsonl`覆盖默认清单。

3. 四卡生成新教师缓存：

```bash
bash sam3_lightweight_tinyvit_stage3_distill_exp/p13_unlabeled_output_distill/scripts/cache_unlabeled_teacher_4gpu.sh
```

4. 四卡从官方TinyViT重新训练：

```bash
bash sam3_lightweight_tinyvit_stage3_distill_exp/p13_unlabeled_output_distill/scripts/train_p13a_4gpu.sh
```

正式配置见`configs/p13a_unlabeled_output_distill.yaml`。训练日志、缓存和权重不提交Git。

## 正式训练结果

四卡正式训练在重启后的`lightning_logs/version_1`完整完成20轮。验证损失最佳点是epoch 16，
正式权重为`weights/p13a_unlabeled_output_distill.epoch16.pt`；最后一轮epoch 19没有继续改善。

| 模型 | checkpoint | `val/supervised` | `val/kd` | `val/loss` |
|---|---|---:|---:|---:|
| P12 Control | epoch 19 | 4.8458 | 4.5571 | 9.4029 |
| P13-A | epoch 16 | 4.8242 | 4.5465 | 9.3707 |
| P13-A最终轮 | epoch 19 | 4.8274 | 4.5475 | 9.3748 |

P13-A与P12使用相同的有标签验证集和损失口径，因此可以直接比较。最佳点相对P12仅下降
`0.0216 supervised`、`0.0106 KD`和`0.0322 total`，说明加入无标签数据没有破坏训练域，
但训练域收益很小，不能仅凭这组loss判断跨场景泛化已经改善。

|---|---:|---:|---:|---:|---:|---:|---:|
| 保留评测 | 100 | 1,301 | 21,285 | 16.36× | 2,768,419 | 15,027,427 | 5.43× |
| 训练候选 | 331 | 5,548 | 72,788 | 13.12× | 13,033,647 | 51,569,998 | 3.96× |
| 未入选 | 160 | 190 | 5,156 | 27.14× | 996,911 | 5,740,497 | 5.76× |

这里的“检测数”包含同一物体上的重复Query，591张图片也没有人工真值，所以不能把数量增长解释为
精度或Recall提升。人工逐页查看联系表并抽查原尺寸结果后的结论是：

- P13-A在真实道路图上确实扩大了跨场景覆盖，雨夜、反光、磨损、航拍和远距离细线的连续性通常
  优于P12，部分P12完全漏掉的白/黄标线和斑马线被恢复；这不是纯粹由重复Query造成的假象。
- 同时，P13-A的置信度校准和类别分离明显退化。同一条标线常被多个提示同时激活，箭头、文字、
  示意图块、车辆和反光区域会被错误覆盖，mask也更粗、更容易把相邻标线连接起来。
- 未入选的160张图片大部分仍保持安静，但少量严重误触发和大量重复Query把总体计数显著拉高，
  因此它不是“所有图片全面崩溃”，也不是可以直接部署的泛化提升。
- 第一版331张训练候选未经人工清洗，包含示意图、拼图、商品图和非道路内容；每轮又被重复使用约
  28次。这两个因素可能进一步放大了错误语义和过拟合，100张保留图也只是同一抓取池的哈希划分，
  还不是严格按来源与场景隔离的域外测试集。

综合判定：P13-A学到了更宽的道路标线外观与更强的域外激活能力，但没有得到干净的泛化胜利；
新增Recall与严重的重复候选、类别混淆和置信度失准同时存在。仅做NMS可以减少重复框，不能修复
语义误检和多类别重复响应。

## 原因与下一步

这一现象与当前无标签损失完全吻合：P13-A只约束与教师高置信实例匹配的学生Query，其余学生Query
不受约束；同时Presence持续接受软蒸馏，因而大量额外Query可以越过0.5阈值。教师未检出又不能被
简单当成hard negative，否则会把教师漏检固化到学生中。

因此暂不直接进入P13-B强弱增强。优先增加一个P13-A候选校准消融，并分别验证以下变量：

1. 缓存教师全部200个候选的连续分类和Presence分布，对未匹配学生Query做软分布/排序约束，
   但不设为硬0；
2. 增加同提示内重复候选的一致性或抑制损失，区分“一个实例多个Query”与真实虚线片段；
3. 将331张无标签图从每轮约28次重复降为可控曝光量，单独验证数据重复强度；
4. 清洗训练清单，并建立按来源和场景隔离的人工标注域外集。
